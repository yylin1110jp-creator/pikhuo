# 拾火創意 PIKHUO 官網

這是一個可直接部署至 GitHub Pages 的靜態網站。HTML、CSS、文字設定、粒子程式與 Google 試算表串接程式皆已分開。

## 先預覽網站

請不要直接雙擊 `index.html`，因為瀏覽器會阻擋模組與 Logo 圖檔讀取。

在網站資料夾開啟終端機後執行：

```bash
python -m http.server 8080
```

再開啟：

```text
http://localhost:8080
```

## 修改文字

開啟 `js/content.js`。首頁標題、流程、服務、合作對象、合作方式、聯絡資訊都集中在這個檔案。

只修改引號內的文字，保留逗號、引號、中括號與大括號。

## 更換方形品牌符號

目前粒子使用：

```text
assets/pikhuo-mark.png
```

如果日後更換檔案，請維持透明背景 PNG，並使用相同檔名。程式會讀取圖片透明度，自動生成粒子座標，不會重新繪製 Logo。

## 粒子視覺邏輯

- Logo 使用原始圖片透明度取樣，不改變比例或輪廓。
- 流程依序轉換為不規則流帶、折疊曲面、粒子渦流、扭帶與左側自由粒子場。
- 六個畫面共用同一批粒子，因此捲動時是連續變形，不會突然換成另一套動畫。
- 主體圖形之外另有低亮度的前、中、後景環境粒子；前景柔焦光點只保留少量。
- 粒子在形狀完成後仍會沿路徑緩慢流動；捲動負責形狀之間的轉換。
- 粒子可以穿過文字後方，文字以沒有明顯邊界的深黑紫柔霧維持閱讀。
- 滑鼠移到服務項目時，對應的粒子流會稍微變亮。
- 手機版會降低粒子數量、關閉滑鼠互動，並提高文字後方柔霧濃度。

## 串接 Google 試算表

1. 開啟準備接收網站合作需求的 Google 試算表。
2. 點選「擴充功能 → Apps Script」。
3. 刪除原本的範例程式。
4. 複製 `google-apps-script/Code.gs` 全部內容並貼上。
5. 按右上角「部署 → 新增部署作業」。
6. 類型選擇「網頁應用程式」。
7. 執行身分選擇「我」。
8. 存取權限選擇允許網站訪客使用的公開選項。
9. 完成授權後，複製結尾為 `/exec` 的網址。
10. 開啟 `js/content.js`，把網址貼到 `formEndpoint`：

```js
formEndpoint: "https://script.google.com/macros/s/你的部署編號/exec"
```

11. 重新上傳網站並實際送出一筆測試資料。

Apps Script 會自動建立「合作需求」工作表與欄位。網站只有在收到後端成功回應後，才會顯示成功訊息。

## 部署 GitHub Pages

把這個資料夾中的全部內容上傳到 GitHub repository 的發布分支。GitHub Pages 的 Source 若使用一般靜態檔案，選擇 `Deploy from a branch`，發布資料夾選擇 repository 根目錄。

網站必須保留以下相對路徑：

```text
index.html
css/style.css
js/content.js
js/main.js
js/particles.js
assets/pikhuo-mark.png
```

## 無動畫與備援

- 使用者開啟「減少動態效果」時，粒子會降低移動與互動。
- 不支援 WebGL 2 或載入失敗時，會改顯示靜態品牌符號。
- 文字內容保留在 HTML，即使粒子程式失敗仍可閱讀。
- 表單尚未填入 Apps Script 網址時，不會顯示假成功。

## 主要檔案

```text
index.html                       網站結構與預設備援文字
css/style.css                    全站視覺、排版與手機版
js/content.js                    可直接修改的文案與聯絡資訊
js/particles.js                  WebGL 粒子、Logo 取樣與形態轉換
js/main.js                       導覽、捲動、表單與一般互動
google-apps-script/Code.gs       Google 試算表接收程式
```

## 2026-10-09 粒子重製

- 桌面：22,000 主體粒子、3,000 環境微塵、7,500 流場粒子、15 個前景光點。
- 手機：5,200 主體粒子、1,200 微塵、2,200 流場粒子、5 個前景光點；DPR 上限 1.25。
- Logo 分成結構 55%、輪廓 25%、高光 7%、游離 13%，依原始透明圖片取樣。
- 使用透視攝影機、Z 軸位置、HDR 高光、EffectComposer／UnrealBloomPass／OutputPass。
- 桌面 Bloom 閾值 1.05，只讓稀疏高光產生光暈；手機與減少動態效果模式關閉 Bloom。
- 前景使用世界座標的透明面片，著色器生成柔焦與緩慢呼吸，避免硬體點精靈尺寸限制。
- 霧光由 GPU 噪聲著色器生成；不使用全畫面景深後製，以保留文字與 Logo 可讀性。
- Three.js 0.180.0 與必要後製模組已附於 js/vendor/three，附 MIT 授權。部署時不需 npm 或 CDN。
- 文字仍修改 js/content.js；視覺主體在 js/particles.js；霧光、流場與前景在 js/atmosphere.js。
- 上傳全部檔案到 GitHub Pages，包含 js/vendor，勿只覆蓋 particles.js。

本次保留上傳版本的單頁架構。原檔的 formEndpoint 為空，表單尚未串接；聯絡資訊沿用原檔，發布前請核對。

字型使用系統中文字型，不再依賴 Google Fonts。瀏覽器驗證：1440×900、390×844 與減少動態效果模式；三種模式渲染成功，無水平溢出、無 JavaScript 或 Shader 錯誤。

## v3：連續文字、粒子擴散與 3D 出場

流程區改為固定閱讀舞台，同一個視窗依序呈現方向、策略、執行與回饋。捲動途中始終有一段文字在場；原本各段 128svh 的大留白已移除。

粒子改為厚環、厚雙螺旋、立體粒子雲、寬幅扭帶與波浪。段落切換時，同一批粒子擴散到整個畫面，再收攏；原始 Logo 在首屏保持比例。閱讀區由文字位置計算，主體粒子在該區降低亮度，背景柔霧保護段落對比。

下方服務、客群與合作卡片從 Z 軸較遠位置，以 X／Y 軸旋轉進場，最後回到正面；服務與客群卡片懸停時微微浮起。手機降低傾斜幅度；減少動態效果模式關閉出場旋轉與過渡。

驗證：桌面、手機與減少動態效果模式，各抽查固定閱讀舞台七個捲動位置，標題皆留在視窗可讀範圍；無 JavaScript／Shader 錯誤、水平溢出或 WebGL 備援。

Facebook 影片連結未能讀取。本版依使用者提供的六張影片截圖借鑑厚環、波浪、粒子擴散等運動方式，不聲稱重現影片時序或效果。

## v4：中央 Logo 與分鏡構圖

首屏：原始品牌符號置中，桌面左右文字。粒子先分布於三維空間，再於 3 秒內旋轉收攏到原始 Logo；匯聚計時在圖片讀取完成且第一幀著色器繪製完成後開始，避免初次編譯耗時跳過動畫。右上斜向柔光由噪聲霧光著色器生成，維持紫色與暖白色系。

流程舞台：主標置於左上、說明位於右下，執行段落互換左右。粒子變成抽象流帶、折疊曲面、渦流與扭帶；轉場中擴散到全畫面、沿 Z 軸向鏡頭推進，接著收攏。未使用手掌。v5 依最新要求，將第一幕改為大樹向下分岔的根系。

服務：桌面右側文字在上，四個服務卡片以 2×2 排列在下；左側是流動的自由粒子場。手機保留 2×2 卡片，窄於 360px 時改為一欄。卡片依交錯方向旋轉、沿 Z 軸進場；下方客群與合作區另有不同的透視出場。

手機採上下構圖：上方 Logo、下方標題與說明；流程文字改為上標題、下說明。減少動態效果模式直接顯示 Logo 與正面內容，關閉匯聚、旋轉與鏡頭推近效果。

可修改文字仍集中在 js/content.js。這次重排的是現有單頁，表單與聯絡資訊仍沿用原檔。

驗證：桌面／手機／減少動態效果，七個流程位置的標題與段落保持可讀；桌面、手機首屏文字與四格服務佈局另行檢查，未出現 JavaScript 或 Shader 錯誤。

## v5：根系與舒緩轉場

只修改粒子圖形及轉場節奏，其餘版面、文字、Logo、光束、服務卡片與聯絡內容保留。

「從想法走向市場」的圖形換成上方主根、向下多層分岔的立體根系；由可重現的分支曲線取樣，包含主根、次根、細根和真實 Z 軸深度。根系程式在 js/root-system.js。

第二、第三段移除 Z 軸前衝與全螢幕爆散，改為側向匯流、輕微垂直展開。每個閱讀段落先保留完整主體，到段落末端才開始變形，降低連續捲動時的視覺負擔。首屏 Logo 匯聚、後續服務區及卡片出場維持原設定。

## v6：匯流、成長與粒子時間隧道

行銷執行的三葉扭結改成三束有厚度的匯流光帶；成效回饋的扭曲環改成五組逐步升高的立體粒子階梯。

只有執行到回饋之間使用時間隧道：18 層斷續粒子環沿 Z 軸前移，中央保留消失點，前後平滑接回圖形。鏡頭不旋轉，沒有整段持續前衝；閱讀區持續壓低粒子亮度。其他段落的轉場與內容維持原設定。減少動態效果模式直接切換穩定圖形。

驗證：1440×900 桌面、390×844 手機及減少動態效果模式，八個流程位置皆無水平溢出、JavaScript／Shader 錯誤或 WebGL 備援；標題與說明保持在可讀範圍。另檢視執行、隧道中段、回饋的實際渲染畫面。

## v7：首屏即時粒子與 Logo 滾動散開

首屏在 HTML 內提供 900 顆輕量 SVG 粒子作為第一個可見畫面，避免等待模組、Logo 解碼及 GPU 著色器時只看到空背景。Import map 提前至 head，預載 Logo 圖檔與 WebGL 模組。完成第一個 GPU 畫面後，底圖平滑淡出，接上原有 3 秒 Logo 匯聚；底圖本身不執行 3D 動畫。

取消原本首屏 48% 的滾動門檻。從首次向下捲動就提高 Logo 的散開程度，首屏前段展開為全畫面粒子，再銜接根系。若使用者在開場匯聚完成前捲動，立即讓滾動取得控制，避免 Logo 再次收攏。其他圖形、隧道與段落內容保留。

驗證：刻意延後粒子模組載入，桌面與手機仍在首個 HTML 畫面顯示 900 顆底圖粒子；下滑 20px 時散開與場景進度皆大於零，且開場匯聚交由滾動接管。桌面、手機與減少動態效果模式的八個閱讀位置均無溢出、JavaScript／Shader 錯誤或 WebGL 備援。
